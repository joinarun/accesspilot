# AccessPilot Agent Spec

## Overview

AccessPilot is an autonomous accessibility repair agent for web applications. It accepts a public URL, local repository path, or GitHub repository URL; renders and scans relevant pages with deterministic accessibility tooling; explains and normalizes findings; maps findings to source; proposes and applies minimal repairs in a local working copy; verifies the repaired application; and prepares a pull request only after an explicit human approval gate.

The implementation is a local, prototype-first Google ADK 2.0 graph workflow. Deployment infrastructure is out of scope for this iteration. The graph uses typed node inputs and outputs, conditional routing, bounded retries, a bounded repair loop, and resumable human input before any remote Git operation.

## Example Use Cases

1. Scan the bundled vulnerable sample app, repair its missing form labels and semantic issues, then show before/after counts and changed files.
2. Inspect a local React, Next.js, Angular, Vue, HTML, or server-rendered project, start it when a safe development command can be determined, discover routes, scan them, and prepare a reviewable patch.
3. Clone a GitHub repository into an isolated working directory, create a local branch, repair accessibility findings, verify the patch, and prepare a PR title/body. Pushing and PR creation remain disabled until the user explicitly approves.
4. Scan a production or staging URL when no source is available, report normalized findings, and mark source repairs as unresolved instead of pretending to fix them.

## Inputs

- Target: website URL, local repository path, or GitHub repository URL.
- Optional branch name, route list or scan depth, WCAG level, authentication instructions, LLM provider, and framework-specific start command.
- Provider selection: `deterministic`, `gemini`, or `openai`. Deterministic mode uses typed local specialists without LLM calls. OpenAI traffic must use the enterprise LLMproxy base URL, never the public OpenAI endpoint directly.

## Tools Required

- Repository loader: validates local paths and clones GitHub repositories into isolated workspaces.
- Framework detector: identifies React, Next.js, Angular, Vue, plain HTML, and common server-rendered projects from manifests and source layout.
- Local app runner: selects allow-listed development commands, manages subprocess lifecycle, and reports local preview URLs.
- Route discovery: combines configured routes, framework conventions, same-origin links, and browser navigation.
- Browser automation: Playwright-based rendering, DOM capture, screenshots, keyboard checks, and preview validation.
- Accessibility scanner: axe-core plus focused deterministic source checks,
  normalized into one typed finding contract.
- Source inspection and mapping: bounded workspace search that excludes secrets, build output, dependencies, and files outside the target root.
- File repair: allow-listed textual edits with path confinement, before/after hashes, dry-run support, backups or git diffs, and no unrelated refactors.
- Verification: repeat scans, issue fingerprint comparison, regression detection, and allow-listed lint/type-check/test/build commands.
- Git and PR preparation: local branch/diff/commit preparation plus provider-neutral PR metadata. Push and PR creation require explicit resumed approval.

All authentication is provided at runtime through environment variables or untracked local configuration. No supplied credential may be copied into source, examples, logs, artifacts, tests, or tracked files.

## Architecture & Specialized Agents

- Accessibility Auditor Agent: interprets deterministic scan evidence and produces plain-language, WCAG-aware issue descriptions.
- Codebase Investigator Agent: maps DOM selectors and snippets to routes, components, templates, styles, and tests.
- Repair Planner Agent: groups related issues and chooses semantic, minimal, low-risk repair strategies.
- Code Repair Agent: applies bounded edits inside the working copy while preserving project conventions.
- Verification Agent: compares before/after scans and runs relevant deterministic checks.
- PR Agent: prepares branch, commit, title, and body metadata; it cannot push or open a PR without approval.

Graph nodes cover intake, repository loading, framework detection, app startup, route discovery, scanning, normalization, planning, source mapping, repair, patch validation, preview, verification, regression checking, human approval, PR preparation/execution, and final reporting. Verification failure may return to repair planning, but a maximum iteration count and repeated-state fingerprint stop infinite loops. Missing source or failed local startup routes to a scan-only fallback. Rejected approval routes directly to a safe final report.

## User Interface

The local web UI contains:

- Project input and provider/configuration controls.
- Filterable scan results with severity, WCAG, route, selector, and evidence.
- Repair-plan cards with proposed files, confidence, and risk.
- Original/fixed preview links, before/after counts, and diff summary.
- PR review with tests, remaining issues, proposed commit/PR text, and explicit approve/reject actions.

The AccessPilot UI itself must meet basic keyboard, focus, label, landmark, contrast, and live-region accessibility requirements.

## Constraints & Safety Rules

- Never push, create a remote branch, publish, deploy, or open a PR without explicit user approval for that exact run.
- Prefer native semantics over ARIA and never silence a scanner without improving the user experience.
- Restrict filesystem and subprocess operations to the selected workspace and allow-listed commands.
- Reject path traversal, unsafe repository URLs, shell injection, credential-bearing URLs, and direct OpenAI base URLs.
- Redact secrets from logs and reports. Do not persist credentials.
- Keep changes minimal and traceable to normalized issue IDs; preserve design unless accessibility requires a visual adjustment.
- Clearly report uncertainty, skipped checks, unsupported frameworks, and issues that cannot be repaired automatically.
- Stop after the configured maximum repair attempts or when the same issue/diff fingerprint repeats.
- Produce reproducible commands for every scan, test, build, and verification result.

## Success Criteria

- A typed ADK 2.0 `Workflow` loads and validates target input and follows the intended conditional graph routes.
- The bundled sample app can be scanned with deterministic tooling and produces known accessibility findings.
- A safe local repair run creates meaningful source changes, then a second scan reports improvement without new critical regressions.
- The UI displays issues, plans, diffs, previews, test results, and approval state.
- Gemini and enterprise-LLMproxy-backed OpenAI models are selected through one provider abstraction without leaking provider details into workflow code.
- Local unit and integration tests cover normalization, routing, loop termination, workspace confinement, provider validation, approval enforcement, and the sample repair flow.
- Behavioral evaluation cases cover scan-only fallback, safe repair planning, rejection of unsafe operations, loop termination, and PR approval behavior.
- Documentation explains setup, configuration, graph topology, provider switching, example use, PR flow, reproducible commands, and known limitations.

## Reference Samples

- `deep-search`: reuse the bounded iterative workflow, structured outputs, and human-review concepts, adapted to ADK 2.0 graph routing.
- `genmedia-for-commerce`: reuse the combined FastAPI plus built SPA serving pattern for a local full-stack experience.

## Non-Goals for This Prototype

- Production deployment, cloud infrastructure, persistent multi-tenant storage, arbitrary authenticated-site login automation, and automatic merging.
- Guaranteed automatic repair of subjective content such as the meaning of alternative text or complex application-specific keyboard behavior.
